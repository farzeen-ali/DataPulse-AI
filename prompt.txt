Mandatory security requirements

SQL security

Use a PostgreSQL compatible parser to validate generated SQL structurally using an AST.

Allow only explicitly approved read only queries.

Reject multiple statements, unauthorized tables or columns, write operations, DDL, dangerous functions, and unsupported query constructs.

Never rely on keyword blocking or the SELECT keyword alone.

Enforce safe row limits, query complexity restrictions, and statement timeouts.

Revalidate every generated query before execution.

Supabase security

Use a dedicated least privilege PostgreSQL role restricted to approved analytics tables.

Never execute AI generated SQL using Supabase service role, database owner, or migration credentials.

Use read only transactions where supported.

Configure runtime and migration database connections appropriately.

Never expose database credentials or Gemini API keys to the frontend.

Prompt injection and AI security

Defend against direct and indirect prompt injection, jailbreaks, malicious instructions, and attempts to override system rules.

Treat user prompts, database records, and model outputs as untrusted input.

Never allow user supplied content or database records to override application security policies.

Prevent unauthorized data access, SQL injection, sensitive information disclosure, and secret exposure.

Never reveal hidden system prompts, internal instructions, or credentials.

Enforce security through deterministic server side controls, restricted database permissions, structural validation, and output validation rather than relying on AI instructions alone.

Controlled SQL self correction

Allow a maximum of two retries for appropriate correctable SQL errors.

Never retry authorization failures or security violations.

Provide only necessary error information to Gemini.

Revalidate every corrected query before execution.

Prevent infinite retries and expensive database operations.

If a question is ambiguous, unsupported, or unsafe, return a clear explanation instead of inventing or executing an unsafe query.
